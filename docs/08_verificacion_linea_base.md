
# Verificación de la línea base documental del SIGR

## 1. Objetivo

Establecer los puntos que se deben revisar antes de considerar aprobada la línea base documental del Sistema Integral de Gestión de Restaurante (SIGR).

La verificación permitirá comprobar que los documentos estén organizados y que su contenido corresponda con el alcance definido para el proyecto.

## 2. Elementos por verificar

| Elemento | Criterio de revisión |
|---|---|
| README.md | Presenta el proyecto y explica su propósito. |
| CHANGELOG.md | Registra los cambios realizados. |
| Descripción general | Explica el objetivo y alcance del SIGR. |
| Módulos funcionales | Incluye los cinco módulos definidos para el sistema. |
| Manual de usuario | Describe los procedimientos previstos para cada perfil. |
| Línea base | Identifica los documentos que forman parte de la versión inicial. |
| Control de cambios | Define cómo se revisan y registran las modificaciones. |
| Estructura de datos | Presenta las entidades y relaciones propuestas. |
| Manual de despliegue | Explica cómo consultar y descargar la documentación. |
| Repositorio | Permite consultar los archivos y su historial. |
| Estructura documental | Mantiene los archivos organizados en las carpetas correspondientes. |

## 3. Casos de verificación documental

### Caso 1. Consulta del repositorio

**Acción:** ingresar al repositorio de GitHub.

**Resultado esperado:** visualizar los archivos principales y la carpeta docs.

### Caso 2. Consulta de los módulos

**Acción:** abrir el documento 02_modulos_funcionales.md.

**Resultado esperado:** encontrar los cinco módulos definidos para el sistema.

### Caso 3. Consulta del manual de usuario

**Acción:** abrir el documento 03_manual_usuario.md.

**Resultado esperado:** identificar los procedimientos previstos para clientes, meseros y administradores.

### Caso 4. Consulta del historial de cambios

**Acción:** revisar el historial de commits del repositorio.

**Resultado esperado:** reconocer los registros de creación y modificación de los documentos.

### Caso 5. Revisión de la línea base

**Acción:** consultar el documento 04_linea_base.md.

**Resultado esperado:** identificar los archivos que conforman la versión documental inicial y sus criterios de aprobación.

### Caso 6. Verificación de la estructura documental

**Acción:** revisar la organización de las carpetas y archivos del repositorio.

**Resultado esperado:** comprobar que los ocho documentos estén ubicados dentro de una sola carpeta docs y que README.md, CHANGELOG.md y LICENSE.txt estén en la raíz del repositorio.

## 5. Criterios para la aprobación

La línea base podrá aprobarse cuando los documentos estén completos, la estructura del repositorio sea correcta y los responsables hayan revisado su contenido.

También deberá quedar identificado el commit exacto que representa la versión aprobada.

La aprobación documental no significa que la aplicación web esté desarrollada o que sus funcionalidades hayan sido probadas. Se refiere a la aceptación de los documentos como referencia inicial del proyecto.

## 7. Conclusión

La verificación documental permite comprobar que los elementos definidos para el SIGR estén organizados y sean coherentes entre sí.

Este proceso facilita el seguimiento de los cambios y permite que los integrantes del equipo trabajen sobre una misma referencia.

Una vez completadas las revisiones y aprobados los documentos, la línea base podrá identificarse mediante una versión específica en el repositorio de GitHub.
